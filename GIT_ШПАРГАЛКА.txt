==================================================================
  GIT — ШПАРГАЛКА ДЛЯ МОДУЛЯ Г (ветка на спринт + pull request)
==================================================================

Что проверяют эксперты на каждом спринте:
  1) есть ветка спринта (sprint1, sprint2 ...);
  2) в ветке лежат исходники проекта, а не архив (.7z/.zip);
  3) сделан pull request (merge request) из ветки спринта в main.

Все команды выполняются в терминале Android Studio (вкладка Terminal внизу),
открытом в папке проекта (там, где лежат settings.gradle.kts и gradlew).


------------------------------------------------------------------
0. ОДИН РАЗ В НАЧАЛЕ
------------------------------------------------------------------
Представиться (имя и почта попадут в историю коммитов):
    git config --global user.name "Vladimir Samoylov"
    git config --global user.email "почта@пример.ru"

Вариант А — организатор выдал пустой репозиторий (ссылка вида https://.../matule.git):
    git init
    git branch -M main
    git remote add origin https://АДРЕС_РЕПОЗИТОРИЯ.git
    git add .
    git commit -m "Начальная версия проекта"
    git push -u origin main

Вариант Б — репозиторий уже с файлами: склонировать его и скопировать
проект внутрь папки клона:
    git clone https://АДРЕС_РЕПОЗИТОРИЯ.git
    (скопировать файлы проекта в эту папку, затем)
    git add .
    git commit -m "Начальная версия проекта"
    git push

Проверить, что в репозиторий НЕ попадает мусор. Файл .gitignore в корне
уже исключает build, .gradle, .idea и local.properties. Посмотреть, что
будет отправлено:
    git status


------------------------------------------------------------------
1. НА КАЖДЫЙ СПРИНТ (X — номер спринта: 1, 2, 3, 4, 5)
------------------------------------------------------------------
Начало спринта — новая ветка от актуального main:
    git checkout main
    git pull
    git checkout -b sprintX

Во время работы — сохранять почаще (хотя бы после каждой задачи):
    git add .
    git commit -m "Спринт X: что сделано"
    git push -u origin sprintX        (первый раз)
    git push                          (дальше)

Конец спринта — pull request:
    1) Открыть сайт репозитория в браузере.
    2) Сайт сам предложит «Create pull request / merge request»
       для ветки sprintX. Если нет — раздел Pull requests -> New.
    3) Откуда: sprintX, куда: main. Заголовок: «Спринт X».
    4) Создать, затем нажать Merge (если эксперты не просили ждать).

После слияния вернуться в main:
    git checkout main
    git pull


------------------------------------------------------------------
2. ТО ЖЕ САМОЕ МЫШКОЙ В ANDROID STUDIO
------------------------------------------------------------------
- Новая ветка: внизу справа имя ветки -> New Branch -> sprintX.
- Коммит: Ctrl+K, отметить файлы, написать сообщение, Commit and Push.
- Отправка: Ctrl+Shift+K (Push).
- Pull request всё равно создаётся на сайте репозитория.


------------------------------------------------------------------
3. ЧАСТЫЕ ПРОБЛЕМЫ
------------------------------------------------------------------
«rejected ... fetch first»  — на сервере есть новые коммиты:
    git pull
    git push

Забыл создать ветку и наделал изменений в main (ещё не закоммитил):
    git checkout -b sprintX           (изменения переедут в новую ветку)

Случайно добавил папку build:
    git rm -r --cached app/build
    git commit -m "Убрана папка build"

Посмотреть историю:
    git log --oneline --graph --all
